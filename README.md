# 製令工時管理（Supabase 雲端版）

線上網址：https://danielchchang.github.io/working-hours/

使用 CRM 相同的電子郵件、密碼登入。工時與 CRM 使用同一 Supabase 專案，但資料表獨立；不同帳號的工時互相隔離。此版本需要網路，仍是單一 index.html，不需 npm 或 build。

## 資料與操作
- `wh_groups`：同來源紀錄共用的製令單號、完成數量與版本。
- `wh_reports`：作業員、工作日、起訖、製令數量、摘要、備註及來源。時數由資料庫生成欄位計算，不能手填；無起訖的歷史紀錄保留原分攤分鐘。
- `wh_records`：遵循 RLS 的 security_invoker 檢視，供前端分頁讀取。
- `wh_imports`：帳號與批次匯入收據，確保重試不重複匯入。
- `wh_seed_rows`：既有帳號專屬的 Excel 初始資料，匿名無法讀取。
- RPC `wh_save`、`wh_delete`、`wh_import`：交易式儲存、刪除標記、備份匯入。資料庫以版本檢查防止舊畫面覆寫新變更。

搜尋、排序、作業員色標、製令合計時數保留。支援手動重新整理、每分鐘更新及視窗重新取得焦點時更新；編輯時保留原版本，遇到衝突需取消編輯後重新整理。

## 舊資料遷移
首次登入，會將目前網址／瀏覽器內 `production-time-reports-v1` 的舊資料遷入該帳號。本機原資料不清除。遷移來源會綁定第一次使用的帳號；切換帳號不會再次傳送同份資料。已存在或已刪除的相同 ID 不覆寫、不復活。

本機 file:// 與線上 HTTPS 的瀏覽器資料各自獨立。如有只存在本機版的新增或修改，請先從舊版匯出備份，再從雲端版「匯入備份」處理。匯入只新增不存在的 ID；相同 ID 不覆寫，若內容已修改應於雲端手動核對。

Excel 來源的共用完成數量只算一次；修改製令單號或完成數量同步同來源工時。歷史紀錄起訖可同時留白保留原分鐘，或填入起訖讓資料庫重新計算。

## 安全與驗證
前端只使用 publishable key。所有工時表均啟用 RLS；匿名不具讀寫權限。sessionStorage 保存目前分頁登入狀態，密碼不由應用程式儲存。

- `supabase/schema.sql`：首次建置的結構、權限與函式；已在現有專案套用，不要重複執行。
- `supabase/verify.sql`：真實資料庫交易測試，結尾 rollback，不留測試紀錄。
- `node tests/cloud.test.cjs`：前端請求、失敗處理與遷移測試。

原始 Excel 初始資料未放入公開原始碼；只保存在帳號受限資料庫與本機忽略檔。Git 歷史的舊版本仍含使用者先前授權公開的內嵌紀錄，並未改寫既有歷史。
